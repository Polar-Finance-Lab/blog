# 실험 로드맵

단계마다 동작하는 결과와 검증 기록을 남긴 뒤 다음 범위로 확장합니다. 현재 아래 구현과 실험은 모두 예정 상태입니다.

<h2 id="core">01. 미니 코어뱅킹</h2>

**상태: 설계 예정**

계좌 개설과 상태, 거래 원장, 잔액, 입출금, 당행 이체를 구현합니다.

완료 기준: 정상 거래와 실패 거래를 검증하고, 동시 이체·서버 재시작 이후에도 잔액과 원장이 일치하는지 확인합니다.

<h2 id="concurrency">02. 동시성과 성능</h2>

**상태: 실험 예정**

비관적 락, 낙관적 락, 조건부 UPDATE를 비교합니다. 균등 부하, 특정 계좌 집중 부하, 양방향 이체를 따로 측정합니다.

기록할 값: 처리량, p95·p99 지연 시간, 충돌·재시도 수, 락 대기 시간, 잔액 불일치 건수. 비교마다 자원과 데이터, 동시 요청 조건을 명시합니다.

<h2 id="distributed">03. 은행 간 송금</h2>

**상태: 실험 예정**

은행 A와 B를 독립 프로세스·DB로 운영합니다. 거래번호, 멱등성, 결과 조회와 상태 전이를 설계하고 지연·응답 유실·프로세스 종료를 재현합니다.

완료 기준: 중복 요청과 결과 미확정 거래를 식별하고, 확인 절차를 거쳐 일관된 최종 결과에 도달합니다.

## 04. 중계·결제·대사

**상태: 확장 예정**

중계 시스템과 은행별 결제 계좌를 모방합니다. 은행 A·B와 중계 기록을 비교하는 대사 배치, 불일치 조회와 재처리 절차를 구성합니다.

## 05. 운영과 장애 실험

**상태: 확장 예정**

메트릭과 분산 추적을 연결합니다. 지연, 호출 실패, 이벤트 중복, 배포 중 종료를 주입하고 장애 범위와 복구 시간을 기록합니다.
