2026년 10월, 금융권에서 개인정보 유출과 침해사고가 연이어 보도됐다. 처음에는 개별 금융회사의 사고로 보였지만, 후속 발표를 보며 문제가 특정 회사나 특정 업권에 국한되지 않는다는 점에 더 주목하게 됐다.

[2026년 10월 14일 금융당국 발표를 전한 연합뉴스 보도](https://www.yna.co.kr/view/AKR20261014134852002)에 따르면, 금융권 침해사고는 총 **16개 금융회사**에서 발생했으며 **약 10만 건의 개인정보 유출**이 파악됐다.

[OK저축은행에서도 대출 신청 페이지를 통한 비인가 접근이 탐지](https://www.newsis.com/view/NISX20261013_0003824586)됐고, 고객 **183명의 개인정보 유출 가능성**이 신고됐다. 해당 정보조회시스템은 차단 조치가 이루어졌으며, 유출 경위에 대한 조사가 진행됐다.

이러한 사고를 살펴보면서 **핵심 금융시스템뿐만 아니라 외부에 노출된 웹 서비스와 API 역시 중요한 보안 점검 대상**이라는 점에 관심이 갔다.

여기서 한 가지 질문이 생겼다.

**정상적인 주문과 결제가 동작하도록 만들었던 내 서비스는, 허용되지 않은 요청까지 제대로 구별하고 있을까?**

## AI 보안 테스트 도구 ARTEX

최근 관심 있게 본 도구 중 하나가 [ARTEX](https://github.com/Autumn-27/ARTEX)다. AI를 활용해 보안 점검을 자동화하는 도구다.

이 도구을 보면서 **이런 도구를 방어적 관점에서 직접 사용해보면 어떨까** 하는 궁금증이 생겼다.

## 앞으로 해볼 것

보안 테스트 대상으로는 과거 우리 FIS 아카데미에서 개발했던 [원큐오더(WON-Q Order)](https://github.com/won-q)를 선택했다. 테이블 QR을 통한 비회원 주문과 결제, 가맹점 주문 관리를 구현한 서비스다. 기존에는 Kubernetes 환경에서 운영했지만, 이번에는 로컬 환경에 다시 구성해볼 생각이다.

<img src="/blog/images/wonq-security-test-architecture.svg" alt="동일한 로컬 네트워크에 연결된 MacBook의 ARTEX 및 Ollama와 Windows의 WON-Q Order 서버, 모의 결제 서버, 테스트 DB 구성도" />

MacBook에서는 ARTEX와 Ollama의 `qwen3:8b` 모델을 실행하고, 같은 로컬 네트워크에 연결된 Windows 노트북에는 WON-Q Order의 주문·결제·카드사·은행 서버를 배포해 정상적으로 실행할 수 있도록 환경을 구성할 예정이다. 이후, ARTEX를 이용해 외부 API, 인증·인가, 주문·결제 처리 과정을 살펴보려 한다.

그리고 실험 중 발견하는 문제와 AI 도구의 분석 과정을 기록하고, 실제 취약점이 확인된다면 원인을 분석하고 수정한 뒤 다시 검증해볼 생각이다
